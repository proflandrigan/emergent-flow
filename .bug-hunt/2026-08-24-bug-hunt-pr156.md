# Bug Hunt Report: PR #156 (feat/data-explorer-pin-to-canvas)

## Summary
- Scope reviewed: All 10 files changed in the PR, plus the `to_payload` contract, the `DataPanel` inspector tab, the `SnapshotNode` canvas component, and the `toReactFlow` IR-to-RF mapping.
- Confirmed findings: 1 Critical, 1 Medium
- Two bugs were found and fixed: a crash on empty DataFrames in the `describe` stats computation (critical, would 422 the entire /execute response), and a stale closure in a React `useMemo` dependency array (medium, would show stale column data when switching nodes).

## Findings

### Critical — `to_payload` crashes on empty DataFrames (no columns)
- **Location:** `emergentflow/server/payload.py:132`
- **Class:** Unchecked edge case / runtime crash
- **Confidence:** Confirmed
- **Description:** `to_payload` unconditionally calls `value.describe(include="all")` on every DataFrame, but `describe()` raises `ValueError: Cannot describe a DataFrame without columns` when the DataFrame has zero columns. A column-less DataFrame can legitimately arise from CSV reads of empty files, upstream filters that match nothing, or API responses with no fields. Because the `describe` call sits outside any try/except, the crash propagates through the server's `_safe_json` wrapper, returning an HTTP 422 for the entire /execute request and wiping every node's results.
- **Evidence / Reproduction:** This test (now in `tests/test_payload.py`) failed with the error before the fix:
  ```python
  def test_empty_dataframe_does_not_crash():
      df = pd.DataFrame()
      payload = to_payload(df)
      assert payload["kind"] == "table"
      assert payload["columns"] == []
      assert payload["describe"] == {}
      json.dumps(payload)  # raised: Cannot describe a DataFrame without columns
  ```
- **Impact:** Any graph whose execution produces a column-less DataFrame will fail the entire /execute response with a 422 error, losing all other nodes' results in that request.
- **Remediation:** Guard the `describe()` call with `if value.columns.empty` — skip the computation entirely for empty-column DataFrames and return `describe: {}`. The fix is at `emergentflow/server/payload.py:130-131`:
  ```python
  describe_stats: dict[str, dict[Any, Any]]
  if value.columns.empty:
      describe_stats = {}
  else:
      desc = value.describe(include="all")
      # ... remainder unchanged ...
  ```

### Medium — Missing `columns` dependency in `useMemo` (stale column data on switch)
- **Location:** `ui/src/inspector/DataPanel.tsx:79`
- **Class:** Stale closure / stale React state
- **Confidence:** Confirmed
- **Description:** The `useMemo` that computes filtered and sorted table rows uses `columns` inside its callback (for the `columns.some(...)` filter check and row-data access) but does not list `columns` in its dependency array. If `columns` changes between renders — e.g., selecting a different node with a different column set — the memoized result would still filter/sort using the old `columns` reference.
- **Evidence / Reproduction:** eslint warns: `React Hook useMemo has a missing dependency: 'columns'. Either include it or remove the dependency array`. The `columns` variable is destructured at line 43 as `const { columns, dtypes, head, shape, describe } = payload;` and used at lines 63 and 69 inside the callback but only `[head, filter, sortCol, sortDir]` are in the deps.
- **Impact:** When a user selects a different output port or a different node while the Data tab is active, the table content would continue to reference the previous node's column set for filtering and sorting, showing wrong or empty results until a re-filter or re-sort triggers a recompute.
- **Remediation:** Add `columns` to the dependency array at `ui/src/inspector/DataPanel.tsx:79`:
  ```tsx
  }, [head, filter, sortCol, sortDir, columns]);
  ```

## Notes & unverified leads
- **`_sanitize_nonfinite` does not handle `np.float32` NaN/Inf** — `np.float32` is NOT a subclass of `float` in numpy ≥ 2.0, so the direct check on line 41 misses it. However, the describe loop converts numpy floats via `.item()` to Python floats before `_sanitize_nonfinite` runs, so this particular path is safe. Other callers of `_sanitize_nonfinite` (the JSON-container path) also receive Python-only values. Unconfirmed that a code path that feeds raw `np.float32` into `_sanitize_nonfinite` exists; kept as an observation.
