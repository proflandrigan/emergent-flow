# Bring Your Own Key

Emergent Flow's LLM nodes (`ef.llm.call`, `ef.eval.run`) never read or store a provider API
key directly. A node's `api_key_env` param (or the `api_key_env` field on an `ef.eval.run`
variant) names an **environment variable** — never the key itself — and the key is resolved
from `os.environ` only at the moment of an actual network call, by `GatewayClient`
(`emergentflow/llm/gateway.py`, [ADR 0017](./adr/0017-llm-nodes-injected-effectful-client.md)). If a
node's `api_key_env` is left unset, its provider falls back to a conventional default env-var
name (`DEFAULT_API_KEY_ENV` in `emergentflow/llm/env.py`):

| Provider | Default env var |
|---|---|
| `anthropic` | `ANTHROPIC_API_KEY` |
| `openai` | `OPENAI_API_KEY` |
| `gemini` | `GEMINI_API_KEY` |

## Setting a key

Export the relevant environment variable before running a graph:

```bash
export ANTHROPIC_API_KEY=<your-api-key>
```

## What never happens

- The graph IR (`.ef.json`) never contains a literal key — only the env-var *name*, if you
  set a non-default `api_key_env`.
- Compiled/exported code (`ef.compile_to_code`) never contains a literal key either — only
  the env-var name, referenced the same way `GatewayClient` reads it.
- A graph you commit or share with a teammate is safe to commit: it names which env var to
  set, never the value.

## Fail-fast checks

- **Before a run starts**, the local server's `/execute`, `/execute/stream`, and
  `/execute_node` endpoints call `emergentflow.llm.secrets.validate_api_keys_present`, which
  checks that every LLM-calling node's resolved env var is actually set and raises a clear
  `MissingAPIKeyError` naming the missing variable — before any node runs, not partway
  through a graph. The error message never echoes a key value, because it never had one to
  echo.
- **A compiled/exported script's docstring** shows you exactly which `export` command(s) you
  need to run it standalone, e.g.:

  ```python
  """Generated by Emergent Flow. Do not edit by hand.

  This script calls an LLM provider. Before running it, set:
      export ANTHROPIC_API_KEY=...
  """
  ```

## Custom provider / env var name

If you're using a provider without a conventional default (or want a non-default env-var
name for an existing provider — e.g. a per-project key), set `api_key_env` explicitly on the
node (or per-variant, for `ef.eval.run`):

```python
ef.llm.call(
    [{"role": "user", "content": "hi"}],
    provider="anthropic",
    model="claude-sonnet-5",
    client=client,
    api_key_env="MY_PROJECT_KEY",
)
```

`client` is the injected `LLMClient` (a `GatewayClient` for a real network call, or a
`ReplayClient` for fixture replay in tests) — see ADR 0017 for why it's threaded through
rather than constructed inside `ef.llm.call` itself.
