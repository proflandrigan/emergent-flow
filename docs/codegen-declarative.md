# Declarative Codegen Seam (Story 8)

`compile_to_code` dispatches on `graph.paradigm`. `Paradigm.FUNCTIONAL` graphs are compiled to a flat, string-template script (Story 5, see [`docs/codegen-compiler.md`](codegen-compiler.md)). `Paradigm.DECLARATIVE` graphs are delegated to `compile_declarative` (`colonymind/codegen/declarative.py`), which compiles a single `nn.module` node whose `subgraph` is a chain of layer nodes into an `nn.Module` subclass. Per [ADR 0008](adr/0008-codegen-templating-vs-ast.md) the class/method structure is built as a real **libcst** concrete syntax tree (not string splicing) — only leaf statement lines go through `cst.parse_statement`. Both paradigms share the same final `ruff format` pass.

## Worked example

`examples/declarative_module.json` defines an `nn.module` node labeled `SimpleClassifier` whose subgraph is a chain of `nn.linear` → `nn.relu` → `nn.linear` layer nodes. Compiling it produces:

```python
"""Generated by Colony Mind. Do not edit by hand."""

import torch.nn as nn


class SimpleClassifier(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear_12864 = nn.Linear(128, 64)
        self.relu = nn.ReLU()
        self.linear_6410 = nn.Linear(64, 10)

    def forward(self, x):
        x = self.linear_12864(x)
        x = self.relu(x)
        x = self.linear_6410(x)
        return x
```

`__init__` assigns one `self.<attr>` per layer, in topological order. `forward` threads a single rolling variable through the chain of layer calls and returns it. The layer attribute names (`linear_12864`, `relu`, `linear_6410`) are derived from the node labels via the Story 3 naming rules — the unicode arrow in labels like `"Linear 128→64"` is stripped during slugification, leaving `linear_12864`.

## Supported surface (the seam, not the catalog)

Only three node types are wired: `nn.module`, `nn.linear`, and `nn.relu`. Any other declarative layer type raises `CodegenError` pointing at **Epic 10**, which owns the full PyTorch layer catalog and tensor-shape-aware codegen. The `forward` generator assumes a single linear chain — general DAG/branching forward bodies are also Epic 10.

## Agent/LangGraph seam

Node types prefixed `agent.` or `langgraph.` are detected and rejected with a `CodegenError` pointing at **Epic 11**. The seam exists and is documented now so the second paradigm (agent/LangGraph graphs) bolts on without a rewrite of the compiler dispatch, per [ADR 0003](adr/0003-sdk-supports-two-paradigms.md).

## Equivalence (ADR 0002)

`cm.execute` has a matching declarative branch (`_execute_declarative` in `colonymind/codegen/executor.py`) that builds the structural twin of the compiled `nn.Module`: an `nn.Sequential` of the same layers, in the same order. Because the layers are constructed fresh rather than loaded from a trained checkpoint, their weights are randomly initialized — the invariant proven here is **structural** (same layer types, params, and order), not numerical. This is verified in `tests/test_codegen_declarative.py`.

`_execute_declarative` returns an inspectable list of layer `repr()` strings under the `"layers"` key (`{module_node.id: {"layers": [...]}}`), not the live `nn.Sequential` module — a live torch module is not a serializable/inspectable artifact per `colonymind.api.is_inspectable`.

## torch is an optional extra

Codegen emits `nn.Module` source with no `torch` installed; `compile_declarative` only builds a libcst tree and never imports torch. `torch` is deliberately **not** a Colony Mind dependency. Only *running* the declarative `cm.execute` path needs torch at call time (imported lazily inside `_execute_declarative`); install it yourself (`pip install torch`) to exercise that path. The structural-equivalence test `pytest.importorskip`s torch, so it is skipped when torch is absent. The full PyTorch layer catalog and tensor-shape codegen are Epic 10.
